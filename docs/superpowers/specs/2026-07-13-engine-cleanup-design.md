# Engine Cleanup/Enhancements — Design (Issue #65)

**Date:** 2026-07-13
**Target version:** v0.26.0
**Scope:** The six engine items from issue #65, plus the AU-2 screen-reader announcement item from `docs/ENHANCEMENTS.md` (approved addition — its natural home is the new `QuizGameShell`).

## Decisions made during brainstorming

- **Chime sounds:** synthesized WAV assets committed to `src/assets/sounds/`, generated by a committed script. No external/licensed audio, plays through the existing `useSoundPlayer` seam.
- **Chime configuration:** reuse the existing `soundEffectsEnabled` setting (v0.23.0). No new setting, no admin UI change.
- **AU-2 live region:** in scope, implemented inside `QuizGameShell`.
- **Shell API:** the game owns `useGameSession` and passes the session object to a presentational `QuizGameShell`. The shell does not call the session hook itself.
- **Wrong-tap chime:** every wrong tap plays the low tone, including non-locking retries under `maxTries`. Timeout also plays the low tone.

## 1. Session events: `lastEvent` in `useGameSession`

Mirror `useMemorySession`'s event mechanism: an `emit(type)` helper sets `lastEvent = { seq, type }` with a monotonically increasing `seq` (so consumers can react to repeated same-type events).

- `handleChoice` emits `'correct'` or `'wrong'` (every wrong tap emits, including retries that don't lock the question).
- `handleTimeout` emits `'timeout'`.
- `restart` resets `lastEvent` to `null`.
- The hook's return value gains `lastEvent` and `soundEffectsEnabled` (already read from settings; exposing it matches `useMemorySession`).

The hook stays audio-free. Consumers (the shell) decide what an event means: chime, live-region announcement. Both session hooks now speak the same event language.

## 2. Orientation pause for quiz games

`useGameSession` consumes `useOrientationGate()` (context default `{ blocked: false }` keeps unit tests, Storybook, and non-gated embeddings unaffected).

- **Input guard:** `handleChoice` early-returns while blocked (same belt-and-braces guard as `useMemorySession.flipTile` — the overlay already makes content inert).
- **Countdown suspension:** the per-question timer effect becomes pause-aware. A `remainingMsRef` initializes to `timeLimitMs` for each question. `blocked` joins the effect's dependencies; when it flips true the cleanup cancels the countdown timeout and the 100 ms elapsed interval and subtracts the consumed span from `remainingMsRef`. On unblock the effect re-arms the timeout with the remaining time and shifts `questionStartRef` forward by the paused span — recorded `timings[].durationMs` and the visible timer both exclude time behind the overlay (same `startRef += pausedSpan` bookkeeping as `useMemorySession`).
- **Elapsed display:** the 100 ms interval does not run while blocked, freezing the `Timer`.
- **Feedback-window edge case:** if rotation happens during the 1.5 s post-answer feedback, the game may advance behind the overlay; the new question's countdown does not arm until unblock, and its clock starts at the unblock moment. No time is stolen from the new question.

## 3. `"orientation": "portrait"` support

- `RECOGNIZED_ORIENTATIONS` in `OrientationGate.jsx` becomes `['landscape', 'portrait']`. The `blocked` computation (`current !== required`) is already direction-agnostic.
- `OrientationOverlay` gains a `required` prop (`'landscape' | 'portrait'`):
  - Portrait uses new i18n keys `common.orientationOverlayHeadingPortrait` / `common.orientationOverlayBodyPortrait` ("Turn it upright!" phrasing consistent with the landscape copy).
  - The icon gets an `orientation-overlay__icon--portrait` modifier whose keyframes rock the 📱 glyph the opposite way (from horizontal back to upright), since the glyph is natively upright. Static under `prefers-reduced-motion`, as today.
- `GameIntro`'s orientation notice gains a portrait branch: `↕️` + new key `common.gameIntroPortrait`.
- New Storybook story and visual-regression baseline for the portrait overlay.

## 4. `QuizGameShell` component

New `src/components/QuizGameShell.jsx` (+ `QuizGameShell.css`), presentational. Props:

```
session,               // the useGameSession return object, owned by the game
manifest,              // icon, name, orientation for GameIntro
onGameEnd,             // forwarded to GameResults' onHome
instructions,          // localized how-to-play string
correctTestId,         // e.g. "correct-color-id" — existing per-game testids preserved verbatim
prompt,                // string, or fn(current) → string/node (character-match interpolates the name)
renderPromptExtra?,    // fn(current) → node rendered between prompt and timer (replay button, swatch)
getChoiceProps?,       // forwarded to GameChoiceGrid
renderChoiceContent,   // forwarded to GameChoiceGrid
renderMissedItem,      // forwarded to GameResults
```

The shell owns everything identical across the three quiz games today:

- `useShellGameStatus({ streak, sessionActive })` (sessionActive = `introResolved && !showIntro && !done`)
- the `settingsLoaded`/`introResolved` null-guard
- `GameIntro` wiring — now passing `manifest.orientation`, so any quiz game adopting the flag gets the intro notice for free
- `GameResults` wiring (score/total/missed/renderMissedItem/difficulty-bump/personal-best/badges)
- hidden `data-testid` span with the correct answer id
- progress/prompt block, `Timer` line (`timerMode !== 'off'`), timeout status row, parent-tap Next button

Plus two new behaviors:

- **Chime layer:** the shell owns its own `useSoundPlayer` instance. On each `session.lastEvent` it plays `chime-correct.wav` (`correct`) or `chime-wrong.wav` (`wrong` and `timeout`) via `getSoundUrl`, gated on `session.soundEffectsEnabled`. The separate player instance means a chime can layer over a still-playing game clip in Animal Sounds — intended: the chime is feedback, the clip is the question.
- **AU-2 live region (WCAG 4.1.3):** a persistent visually-hidden `role="status"` element, present from mount, whose text follows `lastEvent`: new keys `common.answerCorrectAnnounce` / `common.answerWrongAnnounce`; timeout reuses `common.timeUp`. Mirrors the memory game's live-region approach.

Each game's `index.jsx` keeps: data imports, its `useGameSession` call, game-specific effects (Animal Sounds' three audio effects untouched), and the slot props. Roughly 110 → ~40 lines per game; the next quiz game is ~35 lines.

## 5. CSS consolidation

Shared `.game__*` rules move to the component that renders them:

- **`GameChoiceGrid.css`** (new, imported by `GameChoiceGrid.jsx`): `.game__choices`, `.game__choice` base + `:disabled`/`:focus`/`:focus-visible`/`:hover` states, `.game__choice-name` base.
- **`QuizGameShell.css`** (new): `.game__question`, `.game__prompt`, `.game__progress`, `.game__next`, `.game__timeout`.
- **Per-game stylesheets keep only true per-game rules:**
  - animal-sounds: `.game__replay`
  - color-match: `.game__swatch`, `.game__choice--bordered`, `.game__choice-name { color: inherit }` override
  - character-match: `.game__choice-image`, `.game__choice { background: var(--color-surface) }` override, `.game__choice-name` color override
- The shared base takes the majority variant (`font-size: 48px` on `.game__choice`, white `.game__choice-name`); deviations remain as per-game overrides.
- **Acceptance bar: pixel-identical output.** Existing visual-regression baselines are the proof — if a quiz-game baseline shifts, the consolidation is wrong, not the baseline.

This removes the drift pattern that caused the v0.24.1 unstyled-results bug.

## 6. Chime assets

- `scripts/generate-chimes.mjs`: committed, plain Node, no dependencies. Synthesizes two short mono WAVs into `src/assets/sounds/`:
  - `chime-correct.wav` — bright two-note ascending ding, ~0.35 s
  - `chime-wrong.wav` — soft low tone, ~0.3 s
  - Each a few KB (22.05 kHz, 16-bit mono, short envelope to avoid clicks).
- `src/lib/soundLibrary.js` glob widens from `*.mp3` to `*.{mp3,wav}`.

## 9. Testing (positive and negative cases at every layer)

- **`useGameSession` pause (unit, fake timers + `fireEvent`):**
  - Positive: countdown suspends on block and resumes with remaining time; timeout never fires mid-block; elapsed display freezes; recorded `durationMs` excludes the blocked span; `handleChoice` is ignored while blocked.
  - Negative: with no gate in the tree, behavior is unchanged; unblocked sessions behave byte-identically; `timerMode: 'countUp'` sessions survive block/unblock cycles without a countdown appearing.
- **`lastEvent` (unit):**
  - Positive: emits `correct`/`wrong`/`timeout` with increasing `seq`.
  - Negative: `null` before first interaction; `restart` clears it.
- **`OrientationGate` (component):**
  - Positive: `portrait`-required blocks in landscape with portrait copy/glyph, unblocks in portrait.
  - Negative: unrecognized orientation values stay ungated; `landscape` behavior unchanged.
- **`QuizGameShell` (component):**
  - Positive: intro → question → results flow; hidden testid span; timer modes; parent-tap Next; timeout row; chime on correct/wrong/timeout (mock `useSoundPlayer`); live-region text updates per event.
  - Negative: no chime when `soundEffectsEnabled` is false; no Next button in immediate mode; no Timer when `timerMode: 'off'`; live region exists but is empty before the first event.
- **Per-game tests:** existing suites pass with minimal churn — the preserved DOM contract is the proof of the refactor.
- **E2E/visual:** existing quiz baselines unchanged (CSS-consolidation proof); new portrait-overlay story + baseline; page-level a11y checks still pass with the live region present.
