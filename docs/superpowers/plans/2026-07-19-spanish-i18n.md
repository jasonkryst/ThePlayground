# Spanish (es) i18n Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Activate the existing (currently dormant) locale-switching infrastructure by shipping a complete Spanish (`es`) translation — core + all 6 games — and fixing the `useSpeech` en-US-hardcoded speech-language bug that a second locale exposes.

**Architecture:** No new plumbing. `src/i18n/index.js` already auto-discovers `*.json` per locale via `import.meta.glob` and derives `SUPPORTED_LOCALES` from what it finds; `AdminPage`/`LocaleSelector` already render a picker once `SUPPORTED_LOCALES.length >= 2`; `App.jsx`'s `LocaleSync` already calls `i18n.changeLanguage(settings.locale)`. This plan only adds content (`es.json` files) and two small code fixes (`useSpeech.js` locale-aware speech lang, `LocaleSelector.jsx` friendly names).

**Tech Stack:** React 18, i18next + react-i18next, Vitest + React Testing Library + jest-axe, Playwright (e2e + visual regression via Storybook).

## Global Constraints

- Locale code is bare `es` (Latin American/US Spanish vocabulary — e.g. "jugo" not "zumo"), matching the existing bare `en` — not `es-419`/`es-ES`/`es-US`.
- `character-match` and `character-match-bluey`'s character-name catalogs are **not** translated — only their `prompt`/`howToPlay` strings are. The name objects must be byte-identical to their `en.json` counterparts.
- Manifest `name`/`description` fields are never translated, in any game, per `docs/TESTING.md`'s existing convention — out of scope for this work entirely.
- Every new `es.json` must have the exact same key set (namespaces, keys, `{{interpolation}}` placeholders, `_one`/`_other` plural suffixes) as its `en.json` sibling — enforced by a new automated parity test, not just by eye.
- Versioning: `package.json` only, minor bump `0.28.5` → `0.29.0`. No game manifest version bumps (this is core/cross-cutting i18n content, not a per-game feature).
- Out of scope: RTL support, browser-language auto-detection, any locale beyond Spanish.
- Positive **and** negative test cases at every layer touched (standing project preference) — each task below includes both.

- [ ] **Step 1: Add the cross-locale key-parity test (still red)**

Edit `src/i18n/__tests__/i18n.test.js`. Add a new top-level `describe` block at the end of the file (after the existing `describe('buildResources', ...)` block):
```js
function collectLeafPaths(obj, prefix = '') {
  const paths = []
  for (const [key, value] of Object.entries(obj)) {
    const path = prefix ? `${prefix}.${key}` : key
    if (value && typeof value === 'object') paths.push(...collectLeafPaths(value, path))
    else paths.push(path)
  }
  return paths
}

describe('en/es key parity', () => {
  it('has the exact same set of translation keys in en and es across core + every game', () => {
    const enKeys = collectLeafPaths(i18n.getResourceBundle('en', 'translation')).sort()
    const esKeys = collectLeafPaths(i18n.getResourceBundle('es', 'translation')).sort()
    expect(esKeys).toEqual(enKeys)
  })
})
```

```js
import { useCallback, useEffect, useRef } from 'react'
import { useTranslation } from 'react-i18next'

export const SPEECH_LANG_BY_LOCALE = { en: 'en-US', es: 'es-US' }

/**
 * Speaks short text aloud via the Web Speech API (SpeechSynthesis), for games
 * whose prompt is a spoken word. Mirrors useSoundPlayer's shape: speaking a new
 * phrase cancels the previous one, and any in-flight speech is cancelled on
 * unmount. `supported` is false when the browser lacks speech synthesis (or in
 * jsdom), letting callers fall back to on-screen text.
 *
 * @returns {{ speak: (text: ?string) => void, cancel: () => void, supported: boolean }}
 *   Both functions are referentially stable and safe to call when unsupported.
 */
export default function useSpeech() {
  const { i18n } = useTranslation()
  const synth = typeof window !== 'undefined' ? window.speechSynthesis : undefined
  const Utterance = typeof window !== 'undefined' ? window.SpeechSynthesisUtterance : undefined
  const supported = !!(synth && Utterance)

  const synthRef = useRef(synth)
  synthRef.current = synth

  const cancel = useCallback(() => {
    synthRef.current?.cancel()
  }, [])

  const speak = useCallback(text => {
    const s = synthRef.current
    if (!s || !Utterance || !text) return
    s.cancel()
    const utterance = new Utterance(text)
    utterance.lang = SPEECH_LANG_BY_LOCALE[i18n.language] ?? 'en-US'
    utterance.rate = 0.9
    s.speak(utterance)
  }, [Utterance, i18n.language])

  useEffect(() => () => cancel(), [cancel])

  return { speak, cancel, supported }
}
```
