# Manifest name/description i18n Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Translate the two remaining untranslated user-facing strings per game — `manifest.json`'s `name` and `description` — by routing them through the existing i18n system instead of hardcoding English.

**Architecture:** Each of the 6 `manifest.json` files swaps its literal `"name"`/`"description"` for `"nameKey"`/`"descriptionKey"`, pointing into that game's own i18n namespace (mirroring the existing `nameKey` pattern already used for item catalogs). The 6 components that render these fields resolve them via `t()` at render time; `manifests` itself stays inert data built once via `import.meta.glob`.

**Tech Stack:** React 18, i18next + react-i18next, Vitest + React Testing Library + jest-axe.

## Global Constraints

- No plaintext fallback alongside `nameKey`/`descriptionKey` — consistent with the existing item-`nameKey` precedent, which has none.
- No manifest field other than `name`/`description` is affected (`icon`, `color`, `tags`, `version`, `orientation`, `gameType` stay as-is).
- `character-match-bluey`'s `manifestName` value keeps "Bluey" untranslated (licensed proper name) — only the surrounding words translate.
- Versioning: patch bump on all 6 game manifests (this PR edits `manifest.json` itself, unlike the pure-content Spanish i18n PR) + minor bump on `package.json` (`0.29.0` → `0.30.0`) + a new `CHANGELOG.md` entry.
- Positive and negative test cases at every layer touched (standing project preference).
- Continues on branch `105` / PR #110 — do not create a new branch.

- [ ] **Step 1: Write the new key-existence test (still red — no manifest has `nameKey`/`descriptionKey` yet)**

Create `src/__tests__/manifestI18nKeys.test.js`:
```js
import { describe, it, expect } from 'vitest'
import i18n from '../i18n'

const manifestModules = import.meta.glob('../games/*/manifest.json', { eager: true })
const manifests = Object.values(manifestModules).map(m => m.default ?? m)

describe('manifest i18n keys', () => {
  it('every manifest.nameKey resolves to a real translation in en and es', () => {
    for (const manifest of manifests) {
      expect(i18n.exists(manifest.nameKey, { lng: 'en' })).toBe(true)
      expect(i18n.exists(manifest.nameKey, { lng: 'es' })).toBe(true)
    }
  })

  it('every manifest.descriptionKey resolves to a real translation in en and es', () => {
    for (const manifest of manifests) {
      expect(i18n.exists(manifest.descriptionKey, { lng: 'en' })).toBe(true)
      expect(i18n.exists(manifest.descriptionKey, { lng: 'es' })).toBe(true)
    }
  })

  // Negative: catches a manifest that regresses to the old plaintext-name shape
  it('no manifest carries a literal name/description field — only nameKey/descriptionKey', () => {
    for (const manifest of manifests) {
      expect(manifest.name).toBeUndefined()
      expect(manifest.description).toBeUndefined()
      expect(manifest.nameKey).toEqual(expect.any(String))
      expect(manifest.descriptionKey).toEqual(expect.any(String))
    }
  })
})
```
