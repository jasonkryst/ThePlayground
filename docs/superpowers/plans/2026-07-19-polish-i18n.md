# Polish (pl) i18n Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a complete Polish (`pl`) translation — core + all 6 games — as a third locale alongside the existing `en`/`es`, including full CLDR plural-category support (`one`/`few`/`many`/`other`) that Polish grammar requires and `en`/`es` did not.

**Architecture:** No new plumbing. `src/i18n/index.js` already auto-discovers `*.json` per locale via `import.meta.glob` and derives `SUPPORTED_LOCALES` from what it finds; `LocaleSelector` already renders a picker (already visible today, with `en`/`es`); `App.jsx`'s `LocaleSync` already calls `i18n.changeLanguage(settings.locale)`. This plan adds content (`pl.json` files), two small locale-map entries (`useSpeech.js`, `LocaleSelector.jsx`), and rewrites one test (the cross-locale key-parity test) to handle a locale whose plural-suffix set is a strict superset of the others'.

**Tech Stack:** React 18, i18next + react-i18next (v26, `Intl.PluralRules`-backed pluralization — verified empirically: resources with `_one`/`_few`/`_many`/`_other` suffixes for a `pl`-configured instance resolve correctly for counts 1/2/3/4/5/7/11/12/22/100/1.5 with no extra config), Vitest + React Testing Library + jest-axe, Playwright (e2e + visual regression via Storybook).

## Global Constraints

- Locale code is bare `pl` (no regional variant — Polish has none of Spanish's LatAm/Spain ambiguity), matching the existing bare `en`/`es`.
- Register is informal imperative, matching the informal register Spanish used (e.g. `es` "¡Encuentra los pares!" → `pl` "Znajdź pary!").
- `character-match` and `character-match-bluey`'s character-name catalogs are **not** translated — only their `prompt`/`howToPlay` strings are. The name objects must be byte-identical to their `en.json` counterparts.
- Manifest `name`/`description` **are** translated (issue #105 follow-up convention, `docs/TESTING.md:150`) — every game's `pl.json` must translate `manifestName`/`manifestDescription` alongside its other UI strings.
- Polish cardinal plurals use four CLDR categories: `one` (n=1), `few` (n%10∈2..4 and n%100∉12..14), `many` (everything else integer), `other` (non-integers). Both pluralized keys (`common.difficultyOfferHeading`, `gameCard.playCount`) get all four suffixes in `pl.json`; `en`/`es` keep their existing `one`/`other`-only forms, unchanged.
- Every new `pl.json` must have the same base key set (namespaces, keys, `{{interpolation}}` placeholders) as its `en.json` sibling, ignoring plural-suffix differences — enforced by a rewritten automated parity test, not just by eye.
- Versioning: `package.json` only, minor bump `0.30.0` → `0.31.0`. No game manifest version bumps (this is core/cross-cutting i18n content, not a per-game feature).
- Out of scope: RTL support, browser-language auto-detection, any locale beyond Polish.
- Positive **and** negative test cases at every layer touched (standing project preference) — each task below includes both.

with:
```js
const PLURAL_SUFFIX_RE = /_(?:one|few|many|other)$/

function toBaseKey(path) {
  return path.replace(PLURAL_SUFFIX_RE, '')
}

function baseKeySet(locale) {
  return [...new Set(collectLeafPaths(i18n.getResourceBundle(locale, 'translation')).map(toBaseKey))].sort()
}

function pluralSuffixesFor(locale, basePath) {
  return collectLeafPaths(i18n.getResourceBundle(locale, 'translation'))
    .filter(p => p.startsWith(basePath) && PLURAL_SUFFIX_RE.test(p))
    .map(p => p.match(PLURAL_SUFFIX_RE)[0].slice(1))
    .sort()
}

describe('cross-locale key parity', () => {
  it('has the exact same set of base translation keys in en, es, and pl across core + every game', () => {
    const enKeys = baseKeySet('en')
    expect(baseKeySet('es')).toEqual(enKeys)
    expect(baseKeySet('pl')).toEqual(enKeys)
  })

  it('en and es define exactly the one/other plural forms for pluralizable keys', () => {
    expect(pluralSuffixesFor('en', 'common.difficultyOfferHeading')).toEqual(['one', 'other'])
    expect(pluralSuffixesFor('es', 'common.difficultyOfferHeading')).toEqual(['one', 'other'])
    expect(pluralSuffixesFor('en', 'gameCard.playCount')).toEqual(['one', 'other'])
    expect(pluralSuffixesFor('es', 'gameCard.playCount')).toEqual(['one', 'other'])
  })

  it('pl defines all four CLDR plural forms for pluralizable keys', () => {
    expect(pluralSuffixesFor('pl', 'common.difficultyOfferHeading')).toEqual(['few', 'many', 'one', 'other'])
    expect(pluralSuffixesFor('pl', 'gameCard.playCount')).toEqual(['few', 'many', 'one', 'other'])
  })
})
```
(`collectLeafPaths` is the existing helper already defined above this block — unchanged, still used by `baseKeySet`/`pluralSuffixesFor`.)
